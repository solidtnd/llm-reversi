# 対戦ルール

## 盤面・基本ルール

- 8x8の標準的なリバーシ盤、初期配置も標準(中央4マスに石を斜め配置)。
- 黒(先手)・白(後手)が交互に着手する。
- 合法手が存在しない場合は自動的にパスする(LLMに問い合わせない)。
- 両者連続でパスした場合、終局とする。
- 盤面が埋まった場合も終局とする。
- 終局時、石数が多い方の勝ち。同数の場合は引き分け。

## 1手ごとの処理

1. 現在の盤面・合法手一覧をLLMに提示し、着手をJSON形式で応答させる。
2. 応答のJSONパースに失敗した場合、**1回だけ**再試行する。再試行時は、直前の応答がなぜ失敗したか(パースエラーの内容)をプロンプトにフィードバックする(単純な同一プロンプトの再送はしない)。再試行も失敗した場合は反則負けとする。
3. パース成功後、応答内容が合法手一覧に含まれない場合は反則負けとする(リトライしない)。
4. 1手あたりの最大待ち時間(タイムアウト)を超えた場合も反則負けとする。タイムアウト秒数は**30秒**とする。
5. 反則負けとなった場合、理由(非合法手/タイムアウト/パース失敗)を区別して棋譜に記録する([docs/log-schema.md](log-schema.md)の`forfeit_reason`に対応)。

- 反則負けとなった対局は「不成立」として除外するのではなく、**反則負けとして記録し集計に含める**(モデルの安定性を測る指標になるため)。

既存のオセロ棋譜フォーマット(WTHOR/GGF)にはLLM対戦特有の反則負け・リトライという概念自体が存在しないため、これらの扱いは独自に設計する([docs/log-schema.md#既存フォーマットとの関係](log-schema.md#既存フォーマットとの関係)参照)。

## 調整可能な値の管理方針

タイムアウト秒数や得点方式など、ルールとして固定ではなく運用上調整の余地がある値は、コードに埋め込まず**設定ファイルで管理する**([docs/adapter-interface.md](adapter-interface.md)のモデル一覧設定ファイルと同様の方針)。設定ファイルの具体的な配置場所・形式は`engine/`内部構成の検討時に決定する。

## リーグ運営

- 出場モデルの全組み合わせで総当たり戦を行う。
- 同一カード(モデルA vs モデルB)は、先手後手を入れ替えて**2局**(先手・後手1回ずつ)対戦する。

### 得点・ランキングの扱い

- 個々の対局の**勝敗(勝ち/負け/引き分け)は不変の事実として棋譜(`data/`)に記録する**。得点方式の選択によって変わることはない。
- 得点・ランキングは勝敗とは別に、集計時に得点方式(設定値)を適用して算出する。ランキングは**勝点方式**(勝ち=1点/引き分け=0.5点/負け=0点)と**Bradley-Terryモデルによる強さ推定**を併記する。ELOレーティングは、対局を処理する順序によって結果が変わってしまう(逐次更新のため)という性質が本プロジェクトの直感に合わないため不採用とした。詳細は[docs/metrics.md](metrics.md#ランキング指標)を参照。
- 得点方式を事後に変更した場合でも、記録済みの勝敗データから**再計算できる**構成とする。
